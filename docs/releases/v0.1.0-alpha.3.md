# lttl 0.1.0 alpha 3

Adds **signed audit evidence, configurable retention and legal holds** for identity-protected archives.

- Ed25519-signed events and export batches with sequence/hash chaining, independent verification, durable retries and exact-digest storage receipts.
- Separate serverless audit-vault functions and storage adapters for Azure Blob, Amazon S3 and Google Cloud Storage. Deploy under the security team's administration.
- Organization retention defaults and per-archive holds. Held or unexported evidence cannot be pruned; held or retained archive keys cannot be destroyed through the broker. Access expiry and revocation remain separate from preservation.
- Audit recording for archive registration, recipient changes, approval attestations, authentication decisions, key release/denial, revocation, administrator decisions and archive-key destruction.
- Administrator `lttl identity retention` CLI/API commands with fresh IDP authentication. Approval attestations record decisions; they do not implement a two-person approval workflow.
- Replaces the broker's fixed 90-day tracking expiry. Undelivered events no longer expire automatically. Default preservation is indefinite.
- Updated installer includes setup/migration guides, the sharing infographic and public audit-vault deployment sources.

**Upgrade:** Uninstall an earlier desktop version before installing alpha.3; archives and identity profiles are preserved. Stop older broker instances, back up the database, upgrade the broker from this tag, run `--init-db`, and configure signing **before its first upgraded startup**. Preserve legacy audit evidence separately; it is not retroactively signed. Deploy the vault, pin the public key and stream, and configure the export scheduler. Installing the desktop does not deploy or upgrade any cloud service.

**Download:** Use the Windows x64 setup executable and companion SHA-256 file. The installer remains unsigned; the checksum is not an Authenticode signature. Windows 10/11 x64 is required. CPU/portable GPU features remain included, and NVIDIA acceleration/Explorer integration remain optional. Compression algorithms are unchanged.

Validation includes desktop/broker tests, eight vault protocol tests, a real PostgreSQL/TLS contract, and end-to-end IDP/audit/retention tests against the actual release executables and installed client. [Current validation](https://github.com/zeniazenin/lttl-archive/blob/v0.1.0-alpha.3/docs/identity-serverless-validation.md) · [Installer results](https://github.com/zeniazenin/lttl-archive/blob/v0.1.0-alpha.3/docs/windows-installer-validation.json).

**Boundaries:** Live cloud storage/IAM, real IDP policy and serverless deployments still require pilot acceptance. Audit-vault tests use a storage double. External evidence remains held indefinitely until separate security-team disposition. Holds cover broker-managed keys/evidence; archive bytes must be kept in company-controlled retention storage. Neither revocation nor key destruction recalls plaintext or previously retained keys. Retention administration is currently CLI/API only. These features support a compliance program and do not establish HIPAA or SOX compliance.
