# lttl 0.1.0 alpha 2

Adds optional **archive-level access tracking** for encrypted `.lttl` files, with signed webhooks to an organization's security system.

- Enable tracking per archive in the GUI or with `--track-access`; add country watchlist codes using `--alert-country KP`.
- Organizations can require tracking for new archives. The effective policy is saved in the authenticated archive header and enforced by the broker.
- Reports sign-in attempts, verified identities, denials and key release. Unknown identities/locations remain explicitly unknown.
- Durable webhook outbox with HMAC signatures, leased retries across serverless instances, and 90-day event retention.
- Owner-only event retrieval using `lttl identity events` and an authenticated API.

**Deployment:** Upgrade the broker and run `--init-db` before starting the new service. Configure the organization webhook and secrets, schedule the retry dispatcher, and supply organization account membership. Country alerts require signed location estimates from a trusted ingress gateway. No cloud/SIEM resources are deployed automatically.

Download the Windows x64 setup executable and verify it against the companion SHA-256 file. This remains an **unsigned alpha**. Uninstall alpha.1 before installing alpha.2; archives and identity profiles are preserved. Older clients cannot read tracked archive headers, so recipients need this update.

Local validation covers archive-policy tampering, webhook signatures, retries after restart, owner isolation, untrusted location headers, SQLite/PostgreSQL storage and mock-IDP flows through the actual app. Live cloud ingress, SIEM notifications and IDP policies still require pilot testing. Existing CPU/GPU capabilities and compression decisions are unchanged.

Passed: **33 desktop tests**, **10 broker tests**, the separate **PostgreSQL/TLS contract**, **96 end-to-end checks** across 49 mock-IDP sign-ins, and **14 installer checks**. Seven hardware-only desktop tests were skipped. The database-outage check confirms no archive key response is returned when tracking cannot be committed.

Tracking observes requests reaching the broker; it cannot detect offline copies or prove theft. Country estimates can be affected by VPNs/proxies. Country watchlists alert; access blocking remains an IDP policy decision.
